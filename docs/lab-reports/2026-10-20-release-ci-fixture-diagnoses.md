## Current B7 Ubuntu cleanup failure: late HOME read

On exact B7 source [`b7a8511`](https://github.com/mschulkind-oss/yolo-jail/commit/b7a85116d9444f357e715c37e10d389848fe5ff5), [run 39470221544, Ubuntu shard 2 job 118800289951](https://github.com/mschulkind-oss/yolo-jail/actions/runs/39470221544/job/118800289951) failed only `TestAnAttachKeepsThePackTreeTheJailBootedWith`. At `2026-10-20T18:17:50Z`, detached-writer cleanup failed while re-reading Podman's HOME from `/proc/<pid>/environ`: permission denied. The test's attach assertions did not fail. The original integration command exited 1; its package summary was `FAIL .../integration 905.325s`. This is a cleanup-observation failure, distinct from the earlier ARM empty-argv report above.

The sanitized CI record identifies Ubuntu 24.04 and rootless Podman 4.9.3, but does not identify the runner kernel release or the PID's later state. The observed permission failure is consistent with, but does not prove, one Linux procfs exit-path mechanism: upstream [v6.8](https://github.com/torvalds/linux/blob/v6.8/fs/proc/base.c), [v6.14](https://github.com/torvalds/linux/blob/v6.14/fs/proc/base.c), and [v7.0](https://github.com/torvalds/linux/blob/v7.0/fs/proc/base.c) can make a non-directory proc inode root-owned after the process releases its address space, while `environ` remains mode 0400. That can yield EACCES before the PID becomes a zombie. In [v7.2](https://github.com/torvalds/linux/blob/v7.2/fs/proc/base.c), the ownership check changed; [v7.2 fork.c](https://github.com/torvalds/linux/blob/v7.2/kernel/fork.c) returns ESRCH for a missing address space. EACCES also has other permission causes. The CI kernel and this process's cause and eventual fate therefore remain unknown.

An owned local observation on Linux `7.2.9-zen1-1-zen` saw 32 same-UID children through natural exit: 2,567 same-start/live-PF_EXITING, empty-argv polls returned ESRCH, none returned EACCES, and later observations found 2,554 running-state and 13 zombie-state records. In a separate held-process control, a child made itself nondumpable while still live: four HOME reads returned EACCES with PF_EXITING clear. These are local samples, not independent 2,567 children, not a rootless-host reproduction, and not evidence of the CI process's cause.

The narrow candidate adds a permanent fake-probe regression for this late HOME read and a bounded diagnostic made only from already observed identity, argv-following stat/flags/state, and the HOME error class. The test requires the existing fail-closed error and zero signals; wrapping preserves `errors.Is`. It adds no proc reads, retry, wait, or success path, and changes no identity, ownership, deadline, or signal rule. The diagnostic can expose what this failure omitted, but it cannot recover the kernel version or later PID fate from a historical log. A future behavior change still needs evidence that this same identity remains unreadable and what happens to it; EACCES and `PF_EXITING` alone do not prove exit completion. Nothing here claims a race repair, release eligibility, or publication readiness.

## Narrow Linux exit-retention repair

A PID alone is not a stable process identity because the operating system can reuse it. Here, identity pairs the PID with Linux `/proc/<pid>/stat` field 22, the process start-time value. A HOME ownership bracket is a matching HOME observation made while reads before and after it still name that same start time. The first HOME read only finds candidates; it is not ownership proof by itself.

`PF_EXITING` means a Linux task has begun its exit path; it does **not** mean that the PID is gone or that the task is already a zombie. In upstream Linux v7.2, `do_exit()` sets the flag, then `exit_mm()` can release the address space before `exit_notify()` makes the task a zombie. The `/proc/<pid>/cmdline` reader depends on the process address space, so argv can be empty during that interval while a live task is still observable. See the upstream [`do_exit`, `exit_mm`, and `exit_notify`](https://github.com/torvalds/linux/blob/v7.2/kernel/exit.c), [`proc_pid_cmdline`](https://github.com/torvalds/linux/blob/v7.2/fs/proc/base.c), and [`PF_EXITING`](https://github.com/torvalds/linux/blob/v7.2/include/linux/sched.h) sources. This explains a possible Linux mechanism; it does not establish the exact Ubuntu ARM runner kernel's behavior or diagnose the historical Podman process.

The implemented exception in [`integration/preparationworkers_test.go`](../../integration/preparationworkers_test.go) retains a process with empty argv only when all evidence agrees: it was already owned by the test HOME; that ownership was bracketed by equal start times; and the **same post-argv stat observation** supplies a valid live Linux state, the `PF_EXITING` flag, and the same field-22 start time as the listed identity. A later empty or cleared HOME is accepted only for that already-proven PID/start-time pair. The exception is not a general empty-argv retry: malformed, unavailable, or clear flags; invalid or dead states (including `X`/`x`); identity reuse or drift; an unproven, changed, unreadable, or unsupported HOME observation; an unsupported platform; or a zero/expired bound remains visibly fatal. It sends no signal to the retained exiting process; the helper rechecks it until it is gone or dead, or reports the original bound expired.

When the same failure class occurs on the repaired source, the named `empty-argv-observation{…}` diagnostic records the PID/start-time identity, HOME classification, listed and current argv counts/errors, process state and error, flags and error, kill error, observation-read order, and timestamp. The original ARM log predates that diagnostic and contains none of those flags, start-time, or HOME values. The field names describe what a future capture can distinguish; they do not fill the historical evidence gap.

The bounded choice preserves the existing cleanup contract: ownership must be established before a signal, unknown live processes are not guessed away, and the original deadline remains enforceable. This narrow engineering classification required no new owner-policy decision; that is an implementation-scope conclusion, not a recorded owner ruling. It does not authorize treating every empty argv as exit, classifying every `PF_EXITING` process as absent, weakening ownership checks, extending the bound, or skipping cleanup. The minimal repair is safer than those broader shortcuts because the evidence is specific to one already-owned, same-identity process and the exception itself never signals it.

Its focused regression tests failed before and passed after the change; the short integration suite and Darwin/arm64 integration compilation also passed. On that exact source, `just check-ci` passed in 251.130 seconds and the full local integration suite passed in 765.320 seconds. These results validate the local source gates, not the state of PID 13064 in the old ARM run, ARM-hosted CI, rootless Podman, or native macOS. The earlier 934.621-second pass, 760.438-second `cd8b2fe` full run, and 745-second `6ae4053` failure remain historical evidence with the same causal limits.
